# Cities Storage и основание — первый рабочий этап

Ветка `feature/cities-storage` подключает постоянное хранилище, read-only запросы и API основания города.

На старте `ServerMineCitiesPlugin` создаёт `plugins/ServerMineCities/cities.db`, запускает SQLite миграцию `user_version=1`
в одной транзакции и только при успехе публикует `CitiesService` через ServicesManager. При ошибке или версии схемы новее поддерживаемой
плагин отключается без публикации готового сервиса. Новый поток `ServerMineCities-DB` обслуживает чтения; он daemon, закрывается при выключении,
а доступность provider снимается до остановки executor.

Файл схемы создаётся **пустым**: демонстрационная запись автоматически не создаётся. Публичный `CityFoundingService` теперь принимает нормализованное имя,
UUID операции и опорный чанк. Он формирует квадрат 2×2, проверяет доступность загруженного мира, границу мира и настроенные системные запретные зоны.
Проверка Bukkit выполняется в основном потоке; SQLite работает в отдельном executor. По умолчанию основание бесплатно и создаёт стадию `SETTLEMENT`,
нулевую казну и роль `RULER` у основателя. Конфигурация системных прямоугольников находится в `protection.system-zones`; координаты — включительные координаты чанков.

SQLite проверяет геометрию footprint повторно и одной транзакцией создаёт город, резидента, ровно четыре чанка и завершённую запись операции.
Уникальность игрока, имени и чанка проверяется в том же write path. Одинаковый operation UUID с тем же payload возвращает уже созданный город;
повторное использование UUID с другими параметрами даёт `OPERATION_CONFLICT`. Предсказуемые доменные отказы также записываются как `FAILED`, чтобы повтор операции
не изменил результат задним числом. Операции по-прежнему не имеют автоматического восстановления внешней Economy-саги.

Книга реального игрока запускает мастер: фиксирует текущий чанк, принимает название в приватном для сервера чате и просит подтвердить footprint перед созданием.
`/smcities preview` остаётся отдельным read-only макетом, а `/smcities status` показывает готовность хранилища. Реальные покупки дополнительных чанков,
казна, роли и права всё ещё впереди.

Схема резервирует атомарную уникальность чанка по миру и координатам; foreign key-каскад удаляет состав и claims при будущем удалении города.
Ещё не реализованы: UI-мастер создания, безопасное удаление, транзакционный claim, revision compare-and-set, движения казны, saga с Economy и восстановление неизвестного результата после рестарта.
Одной уникальной таблицы недостаточно, чтобы безопасно добавить оплату: будущий write-service обязан владеть общей транзакцией и проверять разрешения.

Проверка этого этапа: Gradle с Java 25 выполнил `:cities:cities-plugin:jar` — **BUILD SUCCESSFUL**.
Эта компиляция/упаковка не запускает автоматические тесты, не создаёт тестовую SQLite базу и не проверяет Minecraft runtime.
