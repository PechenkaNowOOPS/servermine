# Cities Storage — первый этап реализации

Ветка `feature/cities-storage` подключает постоянное хранилище и read-only сервис Cities.

На старте `ServerMineCitiesPlugin` создаёт `plugins/ServerMineCities/cities.db`, запускает SQLite миграцию `user_version=1`
в одной транзакции и только при успехе публикует `CitiesService` через ServicesManager. При ошибке или версии схемы новее поддерживаемой
плагин отключается без публикации готового сервиса. Новый поток `ServerMineCities-DB` обслуживает чтения; он daemon, закрывается при выключении,
а доступность provider снимается до остановки executor.

Файл схемы создаётся **пустым**: основание города и никакая тестовая/демонстрационная запись автоматически не создаются.
Поэтому книга реального игрока сейчас сообщит, что он не состоит в городе. `/smcities preview` остаётся отдельным макетом.
`/smcities status` сообщает `storage ready=true`, но создание, claims и денежные мутации остаются отключены.

Схема резервирует атомарную уникальность чанка по миру и координатам; foreign key-каскад удаляет состав и claims при будущем удалении города.
`city_operations` содержит стабильные operation ID, fingerprint, тело запрошенного intent и состояния recovery;
treasury journal хранится в Cities. Состояние generic journal — база для отдельного saga coordinator, не подтверждение того, что он уже работает.
Ещё не реализовано: доменное создание/удаление, транзакционный claim, revision compare-and-set, записи журнала, saga с Economy и восстановление после рестарта.
Одной уникальной таблицы недостаточно, чтобы безопасно добавить оплату: будущий write-service обязан владеть общей транзакцией и проверять разрешения.

Проверка этого этапа: Gradle с Java 25 выполнил `:cities:cities-plugin:jar` — **BUILD SUCCESSFUL**.
Эта компиляция/упаковка не создаёт тестовую SQLite базу и не проверяет Minecraft runtime.
